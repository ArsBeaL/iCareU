# สรุปสำหรับส่งต่อ

เอกสารนี้เขียนไว้ให้คนหรือ AI ที่มารับงานต่อ อ่านจบแล้วควรทำงานต่อได้ทันทีโดยไม่ต้องถามอะไรเพิ่ม

## โปรเจกต์นี้คืออะไร
เว็บแอปบันทึกยาและอาหารเสริมสำหรับใช้ในครอบครัว ทำงานออฟไลน์ ไม่มีเซิร์ฟเวอร์
ข้อมูลอยู่ใน `localStorage` ของเบราว์เซอร์เครื่องนั้นเท่านั้น deploy บน GitHub Pages
เจ้าของโปรเจกต์คือ Ars BeaL ภาษาหลักที่ใช้คุยงานคือภาษาไทย

## หลักการที่ยึดมาตลอด อย่าเปลี่ยนโดยไม่ถาม
1. **ไม่มี backend และไม่มี dependency ภายนอก** ไม่มี CDN ไม่มี framework ไม่มี build step
   ฟอนต์ใช้ system stack เพื่อให้ออฟไลน์ได้จริง
2. **โครงสร้างไฟล์แบน** `index.html` เป็นไฟล์เดียวที่มีโค้ดทั้งหมด `data.json` เก็บเฉพาะข้อมูลยา
   อย่าแตกเป็นโมดูลหลายไฟล์เพราะจะต้องมี build step
3. **ทุกข้อความต้องมีสองภาษา** ไทยและอังกฤษ ห้ามเพิ่มข้อความที่มีภาษาเดียว
4. **เนื้อหาทางการแพทย์ต้องมีบรรทัดอ้างอิง** และต้องเป็นเอกสารสาธารณะขององค์กรด้านยา
   ห้ามเขียนขนาดยาหรือข้อห้ามจากความจำโดยไม่มีที่มา
5. **ไม่ทำตัวเป็นใบสั่งยา** ทุกบล็อกที่แสดงขนาดยาต้องมีข้อความกำกับว่าเป็นช่วงอ้างอิง
   และต้องให้แพทย์หรือเภสัชกรเป็นผู้กำหนดขนาดจริง
6. **ตรวจงานด้วยภาพหน้าจอจริง** ไม่ใช่แค่อ่านโค้ดแล้วเชื่อว่าถูก

## วิธีทำงานที่ใช้อยู่
พัฒนาแบบวนรอบ แต่ละรอบเจ้าของงานส่งรายการสิ่งที่ต้องการมาเป็นข้อ ๆ
ผู้ทำงานลงมือแก้ ทดสอบด้วย Playwright บน Chromium จริง เก็บภาพหน้าจอมาดู
แล้วรายงานพร้อมบอกข้อจำกัดที่เหลืออยู่ตามตรง ไม่กลบ

## ชุดทดสอบ
ทดสอบด้วย Playwright ผ่าน HTTP server ในเครื่อง ตัว `data.json` ทำให้เปิดแบบ `file://` ไม่ได้อีกต่อไป
สิ่งที่ต้องผ่านทุกครั้งก่อนส่งงาน

- ไม่มี JavaScript error ในทุกหน้าและทุกแผ่นซ้อน
- สร้างโปรไฟล์ ตั้งรหัส ล็อก ปลดล็อก และรีโหลดแล้วข้อมูลยังอยู่
- สลับภาษาแล้วสแกนหาข้อความไทยที่ค้างอยู่ ค่าที่ยอมรับได้คือเหลือเฉพาะชื่อยาที่ผู้ใช้พิมพ์เอง
- เปิดการเข้ารหัส ล็อก ปลดล็อกด้วยรหัสถูกและผิด และตรวจว่า localStorage ไม่มีข้อความธรรมดาหลุด
- กู้รหัสด้วยคำถาม ทั้งกรณีตอบถูกและตอบผิดครบ 3 ครั้ง
- คำนวณขนาดตามน้ำหนักของเด็ก เทียบกับตัวเลขที่รู้คำตอบอยู่แล้ว

## จุดที่พลาดง่าย
- `save()` เป็น asynchronous ภายในและใช้คิวสัญญา ห้ามเรียก `localStorage.setItem` เอง
  จะข้ามการเข้ารหัสและทำข้อมูลรั่ว
- โปรไฟล์ที่เข้ารหัสต้องผ่าน `stripped()` ทุกครั้งก่อนเขียนลง storage หรือส่งออกเป็นไฟล์สำรอง
- การแก้ข้อมูลด้วย regex บนไฟล์ `index.html` เสี่ยงมาก เคยตัดโค้ดหายไปแล้วหนึ่งครั้ง
  ถ้าต้องย้ายข้อมูลก้อนใหญ่ ให้รันสคริปต์ใน Node แล้ว serialize ออกมาแทน
- การสลับภาษากลับเป็นไทยต้องใช้ `untrNode()` ห้ามใช้ `location.reload()` เพราะจะหลุดออกไปหน้าล็อก
- แผ่นที่วาดไปแล้วจะไม่เปลี่ยนภาษาตาม เพราะเนื้อหายาวเลือกภาษาตอนวาด `setLang()` จึงต้องปิดและล้างแผ่นที่เปิดอยู่
- `.mask` ต้องมี z-index สูงกว่า `#lock` ไม่อย่างนั้นแผ่นกู้รหัสจะกดไม่ได้บนหน้าล็อก

## สิ่งที่ยังไม่ได้ทำ
- **การเตือนตอนปิดแอป** ทำไม่ได้ในเว็บที่ไม่มีเซิร์ฟเวอร์ ต้องมี push server ซึ่งขัดกับหลักการข้อ 1
  ตอนนี้เตือนได้เฉพาะตอนเปิดแอปค้างไว้หรือย่อไว้เบื้องหลัง
- **ตารางน้ำหนักครอบคลุม 14 ตัวยา** ยังมียาเด็กอีกหลายตัวที่คิดตามน้ำหนักแต่ยังไม่ได้ใส่
- **แอปยังไม่มีการซิงก์ระหว่างเครื่อง** ย้ายข้อมูลต้องใช้ไฟล์สำรอง
- **คลังยาที่ผู้ใช้เพิ่มเองยังไม่รวมศูนย์** เพราะไม่มีเซิร์ฟเวอร์ ยาที่ผู้ใช้เพิ่มอยู่ในเครื่องนั้นเท่านั้น
  ตอนนี้ทำได้แค่ส่งออกเป็นไฟล์ให้ผู้ดูแลรวมเข้า `data.json` เอง
  ถ้าจะทำให้อัตโนมัติต้องมี backend หรือใช้ GitHub API ซึ่งต้องมี token และขัดกับหลักการข้อ 1
  ทางที่พอเป็นไปได้โดยไม่แตะหลักการคือให้ผู้ใช้เปิด GitHub issue แนบไฟล์เอง
- **ชื่อการค้าต้องตรวจสอบเป็นระยะ** ยี่ห้อและขนาดที่วางขายในไทยเปลี่ยนได้ ควรทานกับฉลากจริงทุกครั้งที่อัปเดต
- **ยังไม่ได้ทดสอบบนอุปกรณ์จริง** ทดสอบบน Chromium ที่จำลองขนาดหน้าจอมือถือเท่านั้น
  โดยเฉพาะ Face ID บน iPhone และการแจ้งเตือนบน iOS ควรลองของจริงก่อนใช้งานยาว
