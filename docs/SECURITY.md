# ความปลอดภัยและความเป็นส่วนตัว

## ข้อมูลอยู่ที่ไหน
ทุกอย่างอยู่ใน `localStorage` ของเบราว์เซอร์เครื่องนั้น ไม่มีการส่งออกไปที่ใด
ไม่มีเซิร์ฟเวอร์ ไม่มีบัญชีผู้ใช้ ไม่มีการเก็บสถิติ
การเชื่อมต่อออกนอกมีอย่างเดียวคือปุ่มค้นจาก openFDA ซึ่งผู้ใช้ต้องกดเอง

**ล้างข้อมูลเบราว์เซอร์แล้วข้อมูลหาย** ควรกดสำรองไฟล์ไว้เป็นระยะ

## รหัส PIN
- เลือกได้ 4 หรือ 6 หลัก จำนวนจุดบนหน้าจอเท่ากับที่เลือกเสมอ ครบแล้วส่งอัตโนมัติ
- เก็บเป็นแฮช PBKDF2 SHA-256 จำนวน 120,000 รอบ พร้อม salt สุ่ม 16 ไบต์ต่อโปรไฟล์
- ล็อกอัตโนมัติเมื่อไม่ได้ใช้งาน ตั้งได้ 1 5 หรือ 15 นาที

## การเข้ารหัสข้อมูล
เปิดได้ที่ ตั้งค่า → ความปลอดภัย → เข้ารหัสข้อมูล ต้องตั้งคำถามกู้รหัสก่อน

**สิ่งที่ถูกเข้ารหัส** รายการยา ประวัติการกิน สถานะการเตือน และข้อมูลร่างกาย
**สิ่งที่ไม่ถูกเข้ารหัส** ชื่อโปรไฟล์ ไอคอน ธีม ภาษา และการตั้งค่าการเตือน
เพราะหน้าล็อกต้องแสดงชื่อและใช้ธีมได้ก่อนปลดล็อก

**วิธีทำงาน**

1. สร้างกุญแจข้อมูลสุ่ม 256 บิต เรียกว่า DEK
2. เข้ารหัสข้อมูลด้วย AES-GCM 256 บิต โดยใช้ DEK
3. ห่อ DEK ไว้สองชุด ชุดหนึ่งด้วยกุญแจที่ได้จากรหัส PIN อีกชุดด้วยกุญแจที่ได้จากคำตอบของคำถามกู้รหัส
4. กุญแจทั้งสองมาจาก PBKDF2 SHA-256 จำนวน 150,000 รอบ พร้อม salt แยกกัน
5. ปลดล็อกคือการแกะห่อ ถ้ารหัสผิด AES-GCM จะตรวจพบเองและแกะไม่ออก

DEK อยู่ในหน่วยความจำเฉพาะตอนปลดล็อกอยู่ พอกดล็อกหน้าจอหรือปิดแอป จะถูกลบทิ้งพร้อมข้อมูลที่ถอดไว้

**ผลที่ตามมา**

- ไฟล์สำรองที่ส่งออกจะเป็นฉบับเข้ารหัส เปิดได้ด้วยรหัส PIN หรือคำตอบเดิมเท่านั้น
- ปลดล็อกด้วยใบหน้ายังใช้ได้ ดูหัวข้อถัดไป
- ต้องเปิดผ่าน `https` เพราะ Web Crypto ใช้ได้เฉพาะใน secure context

## คำถามกู้รหัส
มีคำถามสำเร็จรูป 6 ข้อ หรือจะตั้งคำถามเองก็ได้
คำตอบถูกทำให้เป็นมาตรฐานก่อนเทียบ คือตัดช่องว่างหัวท้าย ยุบช่องว่างซ้ำ และไม่สนใจตัวพิมพ์ใหญ่เล็ก แต่สนใจการสะกด

**เมื่อลืมรหัส PIN**

1. กดลืมรหัส PIN ที่หน้าล็อก
2. ตอบคำถาม ตอบถูกจะเข้าสู่หน้าตั้งรหัสใหม่ทันที ข้อมูลไม่หาย
   ถ้าเข้ารหัสไว้ ระบบจะแกะ DEK จากห่อของคำตอบแล้วห่อใหม่ด้วยรหัสใหม่
3. ตอบผิดครบ 3 ครั้ง จะขึ้นหน้าถามว่าต้องการลบข้อมูลทั้งหมดของโปรไฟล์นี้หรือไม่
   เลือกได้สามทาง ลบทั้งหมด ลองตอบใหม่ซึ่งจะรีเซ็ตจำนวนครั้ง หรือกลับไปใส่รหัส PIN

ถ้ายังไม่ได้ตั้งคำถามไว้และลืมรหัส ทางเดียวคือลบโปรไฟล์แล้วเริ่มใหม่ หรือกู้จากไฟล์สำรอง

## ปลดล็อกด้วยใบหน้าหรือลายนิ้วมือ
ใช้ WebAuthn platform authenticator ซึ่งคือ Face ID บน iPhone ลายนิ้วมือบน Android
และ Windows Hello บนคอมพิวเตอร์ ไม่ได้ใช้กล้องเทียบภาพหน้าเอง เพราะวิธีนั้นหลอกด้วยรูปถ่ายได้

ต้องเปิดผ่าน `https` และเป็นชื่อโดเมนจริง เลข IP ใช้ไม่ได้
กุญแจผูกกับโดเมนและเครื่อง ย้ายเครื่องต้องตั้งใหม่ และรหัส PIN ยังใช้ได้เสมอในฐานะทางสำรอง

### ใช้ร่วมกับการเข้ารหัส
เมื่อเปิดการเข้ารหัสไว้ ระบบต้องได้กุญแจมาถอดข้อมูล ไม่ใช่แค่ยืนยันว่าเป็นเจ้าของเครื่อง
จึงมีสองทางตามความสามารถของอุปกรณ์

**ทางที่หนึ่ง ส่วนขยาย PRF** ถ้าอุปกรณ์รองรับ WebAuthn PRF ซึ่ง Chrome และ Safari รุ่นใหม่รองรับแล้ว
ตัวยืนยันตัวตนจะสร้างความลับ 32 ไบต์ออกมาให้จาก salt ที่แอปเก็บไว้
แอปใช้ความลับนั้นห่อกุญแจข้อมูลไว้อีกชุดหนึ่ง กุญแจไม่ได้ถูกเก็บไว้ที่ไหนเลย
ต้องผ่าน Face ID หรือลายนิ้วมือจริงเท่านั้นจึงจะได้ความลับนี้กลับมา ความปลอดภัยเทียบเท่ากับรหัส PIN

**ทางที่สอง โหมดสะดวก** ถ้าอุปกรณ์ไม่รองรับ PRF แอปจะถามยืนยันก่อน แล้วเก็บกุญแจสำรองไว้ในเครื่อง
ผลคือข้อมูลยังเข้ารหัสอยู่และไฟล์ที่คัดลอกออกไปเปิดไม่ได้ แต่คนที่ใช้เครื่องนี้และเปิดเครื่องมือนักพัฒนาเป็น
จะเปิดข้อมูลได้โดยไม่ต้องรู้รหัส PIN หน้าตั้งค่าจะเขียนกำกับไว้ว่ากำลังใช้โหมดนี้อยู่

ปิดการปลดล็อกด้วยใบหน้าเมื่อไรก็ได้ กุญแจสำรองจะถูกลบทิ้งพร้อมกัน

**ข้อจำกัดที่ต้องรู้** แอปไม่มีเซิร์ฟเวอร์ จึงตรวจลายเซ็นแบบเต็มรูปแบบไม่ได้
ถ้าไม่ได้เปิดการเข้ารหัส การปลดล็อกด้วยใบหน้าเป็นแค่ประตู ไม่ได้ปกป้องตัวข้อมูล

## สรุประดับการป้องกัน

| สถานะ | คนหยิบเครื่องไปเปิด | คนที่เปิด DevTools ดู localStorage |
|---|---|---|
| ไม่ตั้ง PIN | เข้าได้ | อ่านได้ |
| ตั้ง PIN อย่างเดียว | เข้าไม่ได้ | อ่านได้ |
| ตั้ง PIN และเข้ารหัส | เข้าไม่ได้ | เห็นเป็นข้อความสุ่ม |
| เข้ารหัส และใบหน้าแบบ PRF | เข้าไม่ได้ | เห็นเป็นข้อความสุ่ม |
| เข้ารหัส และใบหน้าโหมดสะดวก | เข้าไม่ได้ | อ่านได้ถ้ารู้วิธี |
