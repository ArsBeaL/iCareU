# โครงสร้างโค้ด

## ภาพรวม
`index.html` เป็นไฟล์เดียวที่มี HTML, CSS และ JavaScript ทั้งหมด ไม่มี framework ไม่มี build step
แก้ไขแล้วรีเฟรชเห็นผลทันที ฐานข้อมูลยาที่ยาวมากถูกแยกไปไว้ใน `data.json`

## ลำดับในสคริปต์
1. **ค่าคงที่และตารางข้อมูล** `TAGS` `LIMITS` `UL_AGE` `THAI_RDI` `WEIGHT_DOSE` `AGE_DOSE` `CHILD_WARN` `FORM_UNITS` `STRENGTH_UNITS`
2. **ตัวแปรที่โหลดจากภายนอก** `RULES` `CATALOG` `INFO` ประกาศเป็น `let` ว่างไว้ แล้ว `loadData()` เติมให้ตอนบูต
3. **ฐานข้อมูลผู้ใช้** `DB` เก็บทุกโปรไฟล์ `P` คือโปรไฟล์ที่ใช้อยู่
4. **การเข้ารหัส** `deriveKey` `wrapDEK` `unwrapDEK` `sealJSON` `openJSON` `writeDB`
5. **ตารางเวลา** `isDue` `dosesFor` `dayConflicts`
6. **การคำนวณขนาด** `limitFor` `doseFor` `ageDoseFor` `dailyIntake`
7. **หน้าจอ** `renderToday` `renderMeds` `renderCal` `renderCheckPickers` `renderSettings` สลับด้วย `go(view)`
8. **การเตือน** `tick` ทุก 15 วินาที ดันเข้า `alarmQueue` ให้ `showAlarm` แสดงทีละอัน
9. **สองภาษา** `DICT` `PATT` `tr` `trCore` และ MutationObserver
10. **บูต** `loadData().then(boot).catch(dataError)`

## data.json
```json
{ "version": 1, "rules": [...], "catalog": [...], "info": {...},
  "brands": [...], "sizes": {...} }
```
- `rules` คู่ที่ห้ามกินร่วมกัน 37 กฎ แต่ละกฎมี `a` `b` เป็นรายการแท็ก `sev` `gap`
  ข้อความไทย `t` `d` `x` และอังกฤษ `te` `de` `xe` `k:1` หมายถึงเป็นข้อควรรู้เรื่องขนาด ไม่ขึ้นเตือนบนรางเวลา
- `catalog` 20 หมวด แต่ละรายการเป็น array `[ชื่อไทย, ชื่ออังกฤษ, แท็ก, หน่วย, ปริมาณ, หน่วยปริมาณ]`
- `info` ข้อมูลยา 40 รายการ ไทยใน `u c w s r` อังกฤษใน `ue ce we se re`
- `brands` ชื่อการค้าที่มีขายในไทย 113 ยี่ห้อ แต่ละแถวเป็น array
  `[ชื่อการค้าไทย, ชื่อการค้าอังกฤษ, ชื่อสามัญอังกฤษ, หน่วย, ปริมาณ, หน่วยปริมาณ]`
  ช่องที่สามต้องตรงกับ `en` ของรายการใน `catalog` เพื่อให้สืบทอดสารสำคัญและหมวดมาให้
- `sizes` ขนาดที่มีขายทั่วไป คีย์เป็นชื่อสามัญอังกฤษ ค่าเป็น `[[ปริมาณ, หน่วยปริมาณ, หน่วยนับ], ...]`

## ดัชนีค้นหาชื่อยา
`buildDrugIndex()` รวมสามแหล่งเข้าเป็น array เดียวชื่อ `DRUGS`

1. ทุกรายการใน `catalog` เป็นแถวชื่อสามัญ
2. ทุกแถวใน `brands` โดยสืบทอด `tags` และหมวดจากชื่อสามัญที่อ้างถึง
3. `DB.customDrugs` คือยาที่ผู้ใช้เพิ่มเอง เก็บใน localStorage ไม่ได้อยู่ใน data.json

`searchDrugs(q, n)` ให้คะแนนการจับคู่ ตรงทั้งคำได้ 4 ขึ้นต้นด้วยได้ 3 มีคำนี้อยู่ได้ 2
เรียงชื่อสามัญมาก่อนชื่อการค้าเมื่อคะแนนเท่ากัน และตัดรายการซ้ำที่ชื่อกับขนาดเหมือนกัน

`relatedBlock(d)` สร้างกล่องตัวยาเดียวกันโดยจัดกลุ่มจาก `gen` ซึ่งเป็นชื่อสามัญอังกฤษ

**เพิ่มชื่อการค้าใหม่** เพิ่มแถวลง `brands` โดยชื่อสามัญอังกฤษต้องมีอยู่ใน `catalog` แล้ว
ไม่ต้องแก้โค้ด ระบบจะดึงเข้าดัชนีให้เอง

ไฟล์นี้ถูกแคชโดย service worker จึงยังใช้งานออฟไลน์ได้ปกติ

## โรคประจำตัว
`data.json` มี `conditions` แต่ละรายการมี `id` `th` `en` `cat` `note` `meds` `avoid` `watch` `src`
โดย `meds` และ `avoid` อ้างถึงแท็กใน `TAGS` ชุดเดียวกับที่ใช้ตรวจคู่ยา จึงไม่ต้องมีระบบจับคู่แยก

`conditionChecks()` วนโรคที่ผู้ใช้ระบุ แล้วเทียบแท็กของยาที่ใช้อยู่กับ `avoid` เพื่อสร้างคำเตือน
และเทียบกับ `meds` เพื่อบอกว่ายากลุ่มไหนที่มักใช้แต่ยังไม่พบในรายการ
โรคที่ผู้ใช้เลือกเก็บใน `P.body.conditions` เป็นรายการของ `id`

**เพิ่มโรคใหม่** เพิ่มลง `conditions` ใน `data.json` แท็กที่อ้างถึงต้องมีอยู่ใน `TAGS` แล้ว
ไม่ต้องแก้โค้ด และต้องใส่ `src` เสมอ เนื้อหาทางการแพทย์ที่ไม่มีที่มาไม่ควรอยู่ในแอปนี้

## หน่วยวัด
`P.settings.units` มีค่า `metric` หรือ `imperial`

**กฎเหล็ก เก็บเป็นเมตริกเสมอ** น้ำหนักเก็บเป็นกิโลกรัม ความยาวเก็บเป็นเซนติเมตร
แปลงเฉพาะตอนแสดงและตอนรับค่าจากผู้ใช้เท่านั้น ห้ามเก็บค่าที่แปลงแล้วลงฐานข้อมูลเด็ดขาด
ไม่อย่างนั้น BMI, BMR, TDEE, WHtR และขนาดยาที่คิดตามน้ำหนักจะเพี้ยนทั้งหมด

ตัวช่วย `kgToDisp` `dispToKg` `cmToDisp` `dispToCm` `showMass` `showLen`
และ `cmToFtIn` `ftInToCm` สำหรับส่วนสูงแบบฟุตนิ้ว

ในทะเบียนบันทึกรายวัน ใส่ `conv:'mass'` หรือ `conv:'len'` ให้รายการนั้น
แล้วตัวเรนเดอร์จะแปลงค่า ป้ายหน่วย และขอบเขตต่ำสุดสูงสุดให้เอง

**ขนาดยาไม่แปลง** มิลลิกรัม ไมโครกรัม และมิลลิลิตร คงเดิมเสมอ

## บันทึกประจำวัน
`P.daily[YYYY-MM-DD]` เก็บค่าที่บันทึกรายวัน อยู่ใน `VAULT_FIELDS` จึงถูกเข้ารหัสไปพร้อมข้อมูลอื่น

รายการที่บันทึกได้ประกาศไว้สองที่
```js
DAILY_GROUPS = [{id:'body', ic:'⚖️', th:'...', en:'...'}]
DAILY_FIELDS = [{g:'body', id:'weight', type:'num', th:'น้ำหนัก', en:'Weight',
                 uth:'กก.', uen:'kg', min:1, max:400, step:0.1, ph:'62'}]
```
`dailySheet(date, back)` วาดฟอร์มจากทะเบียนนี้ทั้งหมด **เพิ่มสิ่งที่ต้องบันทึกใหม่ได้โดยเติมหนึ่งบรรทัด**
ไม่ต้องแตะโค้ดหน้าจอ ชนิดที่รองรับตอนนี้

| ชนิด | ใช้กับ | เก็บเป็น |
|---|---|---|
| `num` | ตัวเลข รองรับ `conv:'mass'` หรือ `'len'` เพื่อแปลงหน่วย | number |
| `time` | เวลา | `'HH:MM'` |
| `scale` | ให้คะแนนพร้อมไอคอน ระบุตัวเลือกด้วย `opts:'ชื่อชุด'` | number |
| `text` | ข้อความยาว | string |

ตัวเลือกของ `scale` ประกาศไว้ใน `DAILY_OPTS` เช่น `DAILY_OPTS.SLEEP_Q`
แต่ละตัวเลือกเป็น `{v, ic, th, en}` แตะปุ่มเดิมซ้ำเพื่อยกเลิกค่าได้

`dailyRows(fs, d)` เป็นตัววาดช่องกรอก จัดช่องตัวเลขและเวลาให้อยู่แถวเดียวกันได้เอง
ส่วน `scale` และ `text` จะขึ้นบรรทัดใหม่เสมอ

ตัวช่วยที่ควรใช้แทนการเข้าถึง `P.daily` ตรง ๆ
- `dayLog(ds)` อ่านบันทึกของวันนั้น
- `setDayValue(ds, key, val)` เขียนค่าเดียว ลบคีย์ที่ว่างและลบวันที่ว่างเปล่าให้เอง
- `latestDaily(key)` ค่าล่าสุดพร้อมวันที่
- `latestVitals()` ความดันและชีพจรล่าสุด ใช้แทนการเก็บซ้ำในโปรไฟล์
- `dailyStats()` และ `pruneDaily()` สำหรับดูขนาดและเก็บกวาด

**ข้อตกลงเรื่องแหล่งข้อมูลจริง** น้ำหนักและรอบเอวมีสองที่ คือ `P.body` ซึ่งเป็นค่าปัจจุบัน
และ `P.daily` ซึ่งเป็นประวัติ การบันทึกของวันนี้จะอัปเดต `P.body` ให้ด้วย
ส่วนการแก้บันทึกย้อนหลังจะไม่แตะ `P.body` เพื่อไม่ให้ค่าปัจจุบันเพี้ยน

## แนวโน้มย้อนหลัง
`TRENDS` ประกาศว่ามีอะไรให้ดูได้บ้าง แต่ละรายการอ้างถึงคีย์ใน `P.daily` โดยตรง
หรือใช้ `calc` เมื่อค่าต้องคำนวณ เช่น ชั่วโมงการนอนและพลังงานที่กิน
ส่วน `dual` ใช้กับค่าที่มีสองเส้นอย่างความดัน

`sparkline(series, t)` วาด SVG เอง ไม่มีไลบรารีภายนอก
คำนวณช่วงแกนตั้งจากค่าต่ำสุดและสูงสุดแล้วเผื่อขอบ 15 เปอร์เซ็นต์

**ห้ามเพิ่มการสรุปเชิงสาเหตุลงในหน้านี้** เช่น บอกว่านอนน้อยทำให้ความดันขึ้น
ข้อมูลที่ผู้ใช้กรอกเองไม่มีทางพิสูจน์ความเป็นเหตุเป็นผลได้
บอกได้แค่ทิศทางของตัวเลขในช่วงที่บันทึกไว้

## ผลตรวจเลือด
เก็บเป็น **มก./ดล. เสมอ** เหมือนหลักเดียวกับน้ำหนักและส่วนสูง
`P.settings.labUnits` มีค่า `mgdl` หรือ `mmol` ใช้แปลงตอนแสดงเท่านั้น

ตัวคูณต่างกันตามชนิดสาร จึงมี `conv` สามแบบคือ `glu` `chol` และ `trig`
เพิ่มค่าตรวจใหม่ต้องเลือก `conv` ให้ถูกชนิด ไม่อย่างนั้นตัวเลขจะเพี้ยนเมื่อสลับหน่วย

`ldlTarget()` เลือกเป้าหมายจากโรคประจำตัวใน `P.body.conditions`
ถ้าจะเพิ่มโรคที่มีผลต่อเป้าหมาย ให้แก้ที่ฟังก์ชันนี้จุดเดียว

## รอบเดือน
`periodRuns()` จับกลุ่มวันที่มีค่า `flow` ที่ต่อเนื่องกันเป็นรอบ
`cycleInfo()` คำนวณความยาวรอบจากระยะห่างระหว่างวันเริ่มของแต่ละรอบ
ตัดค่าที่ต่ำกว่า 15 หรือสูงกว่า 60 วันออกก่อนหาค่าเฉลี่ย

หมวดนี้ใช้ `when:'cycle'` ใน `DAILY_GROUPS` และ `cycleOn()` เป็นตัวตัดสินว่าจะแสดงหรือไม่
ซึ่งดูทั้งเพศในโปรไฟล์และสวิตช์ในหน้าตั้งค่า
**การปิดสวิตช์ต้องไม่ลบข้อมูล** เพราะผู้ใช้อาจเปิดใหม่ภายหลัง

ห้ามเพิ่มการคาดการณ์ช่วงไข่ตกหรือช่วงมีโอกาสตั้งครรภ์ลงไป
ความแม่นยำไม่พอและมีผลต่อการตัดสินใจเรื่องคุมกำเนิด

## อารมณ์และความเครียด
`moodConcern()` ตัดสินว่าควรขึ้นการ์ดชวนคุยหรือยัง เกณฑ์คือบันทึกระดับ 1 หรือ 2
ติดต่อกัน 3 วัน หรือรวม 4 วันใน 14 วันหลังสุด และต้องมีข้อมูลอย่างน้อย 3 วันจึงจะเริ่มพิจารณา

**เกณฑ์นี้ตั้งให้ไม่ไวโดยตั้งใจ** ถ้าจะปรับ ให้ปรับในทางที่ไวน้อยลงเท่านั้น
การขึ้นการ์ดบ่อยเกินไปทำให้ผู้ใช้เลิกสนใจ และทำให้แอปกลายเป็นเครื่องมือตัดสินคน

`supportCard()` เป็นเนื้อหาการ์ด ห้ามเปลี่ยนให้กลายเป็นการวินิจฉัย ห้ามใส่คะแนนคัดกรอง
และห้ามย้ายไปแสดงบนหน้าวันนี้

## อาหารและโภชนาการ
`data.json` มี `foodCats` และ `foods` แต่ละรายการเป็น array
`[ชื่อไทย, English, หมวด, หน่วยไทย, serving EN, kcal, คาร์บ g, โปรตีน g, ไขมัน g, มล.]`

**พลังงานคำนวณจากสารอาหารหลักเสมอ** ตอนสร้างข้อมูลใช้ `kcal = round((4c + 4p + 9f) / 5) * 5`
เพิ่มอาหารใหม่ต้องคำนวณด้วยสูตรเดียวกัน ไม่ควรใส่ kcal ที่ขัดกับสารอาหารหลัก

อาหารที่บันทึกแล้วเก็บใน `P.daily[ds].meals` เป็น **สำเนา** ของค่าตอนนั้น ไม่ได้อ้างถึงดัชนีในฐานข้อมูล
เพื่อให้ประวัติเก่าไม่เพี้ยนเมื่อแก้ไขฐานข้อมูลอาหารในภายหลัง

`mealTotals(ds)` รวมพลังงาน สารอาหารหลัก และปริมาตรเครื่องดื่มของวันนั้น
ช่อง `ml` ของเครื่องดื่มถูกนำไปรวมใน `renderWater()` โดยอัตโนมัติ

หมวดที่ต้องการหน้าตาเฉพาะ ให้ใส่ `custom:'food'` ใน `DAILY_GROUPS`
แล้ว `dailySheet()` จะเรียกฟังก์ชันวาดของหมวดนั้นแทนตัวเรนเดอร์ทั่วไป

**อาหารที่ผู้ใช้เพิ่มเอง** เก็บใน `DB.customFoods` แล้ว `loadCustomFoods()` ผลักเข้า `FOODS` ตอนบูต
จึงค้นเจอเหมือนรายการในฐานข้อมูลหลัก ใช้หมวด `mine`

**การค้นออนไลน์** `offSearch(q)` เรียก Open Food Facts ซึ่งเปิด CORS และไม่ต้องใช้กุญแจ
ถ้าล้มเหลวต้องไม่บล็อกผู้ใช้ ให้กรอกเองได้เสมอ
พลังงานคำนวณจากสารอาหารหลักเมื่อมีข้อมูล ไม่ได้ใช้ค่า kcal ที่ปลายทางส่งมาตรง ๆ
เพื่อให้สอดคล้องกับฐานข้อมูลหลักที่ใช้สูตร 4-4-9 เหมือนกัน

## ไทม์ไลน์บันทึกประจำวัน
`dayEvents(ds)` รวมมื้ออาหารกับหมวดที่มีข้อมูลให้เป็นรายการเดียว เรียงตามเวลา
มื้ออาหารเก็บเวลาไว้ที่ `m.t` ตั้งให้อัตโนมัติตอนเพิ่ม ส่วนหมวดอื่นเก็บที่ `d.tm[groupId]`
หมวดการนอนใช้เวลาตื่นเป็นตำแหน่งบนไทม์ไลน์

**เจตนาที่แยกไทม์ไลน์นี้ออกจากรางเตือนกินยา** รางยามีตรรกะซับซ้อนอยู่แล้ว
ทั้งแถบเชื่อมคู่ยาที่ต้องจับคู่การ์ดที่อยู่ติดกัน เส้นบอกเวลาปัจจุบัน และการนับถอยหลัง
การยัดรายการอื่นเข้าไปจะทำให้ตรรกะเหล่านั้นพัง จึงใช้หน้าตาแบบเดียวกันแต่แยกส่วนกัน

## ยาที่แพ้
เก็บใน `P.body.allergies` เป็นรายการของ `{label, tags}`
`allergyHits(med)` เทียบสองทาง คือแท็กของยาตัดกับแท็กของสิ่งที่แพ้ หรือชื่อยามีคำที่แพ้อยู่ข้างใน
เรียกใช้ในสามจุด แถบหน้าวันนี้ การ์ดหน้าสุขภาพ และกล่องยืนยันใน `saveDraft()`

## ระบบสองภาษา ทำงานสองชั้น
**ชั้นข้อมูล** เนื้อหายาวที่มีผลต่อความปลอดภัยเขียนเป็นฟิลด์คู่ภาษาในตัวข้อมูล
เวลาแสดงผลใช้ `RT(rule, field)` และ `IX(info, field)` ส่วนคำเชื่อมสั้น ๆ ใช้ `Lx(ไทย, อังกฤษ)`

**ชั้นส่วนติดต่อผู้ใช้** ปุ่ม ป้าย และ tooltip ใช้พจนานุกรม `DICT` คู่กับ `PATT` สำหรับข้อความที่มีตัวเลขแทรก
และ MutationObserver ที่แปลทุกอย่างที่เพิ่งวาดใหม่

การแปลเป็นทางเดียว ไทยไปอังกฤษ ตอนแปลจึงเก็บข้อความไทยเดิมไว้ที่ `node.__th`
และแอตทริบิวต์เดิมไว้ที่ `el.__thAttr` เพื่อให้ `untrNode()` คืนค่ากลับได้ตอนสลับเป็นไทย
โดยไม่ต้องรีโหลดหน้า ซึ่งจะทำให้หลุดออกไปหน้าล็อก
คำแปลของชื่อสาร ชื่อยา วัน เดือน และหน่วย สร้างอัตโนมัติด้วย `buildAutoDict()`

## วิธีเพิ่มข้อมูล

**กฎคู่ยาใหม่** เพิ่มลง `rules` ใน `data.json`
```json
{"a":["zinc"],"b":["calcium"],"sev":"mod","gap":120,
 "t":"หัวข้อสั้น ๆ","d":"เกิดอะไรขึ้นในร่างกาย","x":"ผู้ใช้ควรทำอย่างไร","s":"แหล่งอ้างอิง",
 "te":"Short title","de":"What happens","xe":"What to do"}
```
`sev` มี `high` ห้ามกินพร้อมกัน `mod` ควรเว้นระยะ `low` ระวัง `good` เสริมกันดี
`gap` คือนาทีที่ควรเว้น ใส่ 0 เมื่อเว้นเวลาไม่ช่วย

**ยาใหม่ในแคตตาล็อก** เพิ่มลง `catalog` ในหมวดที่ต้องการ ไม่ต้องทำอะไรเพิ่มเรื่องภาษา
เพราะมีชื่ออังกฤษอยู่ในตัวข้อมูลแล้ว

**ข้อมูลยาใหม่** เพิ่มลง `info` โดยใช้ชื่อแท็กเป็นคีย์ ใส่ให้ครบทั้ง 5 หัวข้อทั้งสองภาษา

**สารหรือกลุ่มยาใหม่** เพิ่มใน `TAGS` ใน `index.html` ต้องมี `th` `en` และ `kw`
โดย `kw` คือคำที่ใช้เดาจากชื่อที่ผู้ใช้พิมพ์

**ยาที่คิดตามน้ำหนัก** เพิ่มใน `WEIGHT_DOSE`
```js
tag:{mode:'dose', lo:10, hi:15, doses:4, capDose:1000, capDay:4000,
     capDayPerKg:75, tab:500, syr:[120,5], minAge:0.5,
     th:'คำอธิบายไทย', en:'English note', s:{th:'อ้างอิง', en:'source'}}
```
`mode:'dose'` คือ มก. ต่อกิโลกรัมต่อครั้ง `mode:'day'` คือต่อกิโลกรัมต่อวันแล้วหารด้วย `doses`

**ข้อความ UI ใหม่** เพิ่มคู่ไทยอังกฤษใน `DICT` ถ้ามีตัวเลขแทรกให้เพิ่มเป็น regex ใน `PATT`

## สร้าง data.json ใหม่จากซอร์ส
ถ้าย้ายข้อมูลกลับเข้ามาในสคริปต์แล้วอยากแยกออกอีกครั้ง ใช้วิธีรันสคริปต์ใน Node
โดยสตับ DOM ด้วย Proxy แล้ว serialize ตัวแปรออกมา ไม่ควรใช้การตัดข้อความด้วย regex
เพราะข้อมูลถูกประกอบจากหลายบล็อก

## วันที่
`P.settings.dateFmt` มีค่า `dmy` `thai` `slash` หรือ `iso`
`fmtDate(ds)` ใช้กับวันที่แบบสั้น `thDate(d)` ใช้กับหัวหน้าวันนี้ และทั้งคู่เคารพการตั้งค่าเดียวกัน
ปีพุทธศักราชผูกกับรูปแบบ `thai` เท่านั้น ไม่ได้ผูกกับภาษา
`dateField(id, val, ph)` สร้างช่องวันที่ที่แสดงข้อความตามรูปแบบ โดยวาง `input[type=date]` โปร่งใสทับไว้
เพื่อให้ยังใช้ตัวเลือกวันที่ของระบบได้

## แผ่นซ้อนและทางกลับ
`openSheet(html, back)` รับฟังก์ชันทางกลับได้ ปุ่มปิดของแผ่นที่ซ้อนอยู่เรียก `dismissSheet()`
ซึ่งจะปิดแล้ววาดแผ่นเดิมกลับมา ส่วน `closeSheet()` คือปิดแล้วจบ ใช้ตอนที่จะเปิดแผ่นอื่นต่อเอง
เวลาเพิ่มแผ่นที่เปิดจากตัวแก้ไข ให้ส่ง `openEditorSheet` เป็น `back` เสมอ

## การแจ้งเวอร์ชันใหม่
`sw.js` ไม่เรียก `skipWaiting()` เองตอนติดตั้ง ตัวใหม่จึงรออยู่ในสถานะ waiting
หน้าเว็บฟัง `updatefound` และตรวจ `reg.waiting` เพื่อขึ้นแถบให้ผู้ใช้กด
เมื่อกดจะส่งข้อความ `SKIP_WAITING` ไปให้ service worker แล้วรอ `controllerchange` เพื่อรีโหลดหนึ่งครั้ง
`updReloading` กันการรีโหลดซ้ำ และมี `setTimeout` สำรองเผื่อ `controllerchange` ไม่มา

**เวลาปล่อยของใหม่ต้องเพิ่มเลขทั้งสองที่** `CACHE` ใน `sw.js` และ `APP_VERSION` ใน `index.html`
ถ้าลืมเพิ่ม `CACHE` เบราว์เซอร์จะมองว่าไฟล์เดิมและไม่แจ้งอะไรเลย

## ข้อควรระวังเวลาแก้โค้ด
- `save()` เป็น asynchronous ภายใน แต่เรียกแบบไม่ต้อง await ได้ เพราะใช้คิวสัญญาต่อกัน
  ห้ามเขียน `localStorage.setItem` เองตรง ๆ จะข้ามการเข้ารหัส
- โปรไฟล์ที่เข้ารหัสไว้จะไม่มีฟิลด์ `meds` `logs` ใน localStorage ต้องผ่าน `stripped()` เสมอตอนเขียน
- z-index ที่ใช้อยู่ nav 40, lock 100, mask 110, ตัวเลือกเวลา 200, tooltip 300, toast 140
